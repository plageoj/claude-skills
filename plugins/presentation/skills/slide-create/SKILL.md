# 資料からスライドを作る

最初に `../slide-review/references/principal.md` を読む（`../` で始まるパスは、このスキルのフォルダから見たもの）。スタイルの定義と、資料から作るときの決まり（4.5: 削った情報はノートへ、元にないものは足さない）がそこにある。

## 1. 入力

読み取れなければ AskUserQuestion でまとめて訊く: 元の資料、使い道と時間（発表時間か動画の尺）、聴衆。任意で、持ち帰ってほしいこと（元から一文で言えなければ訊く）と出力先（既定は元と同じフォルダの `slides.md`）。

## 2. 元を読む

- スライド: `python ../slide-review/scripts/analyze.py <元> <作業ディレクトリ>` で全文・ノート（`analysis.json`）とページ画像（`full/`）を取る。pymupdf が要る（なければ一時ディレクトリの venv に入れる）。形式ごとの用意は slide-review の SKILL.md の 2。
- **ノートを取りこぼさない**。pptx は python-pptx がないとノートが黙って抜けるので先に入れる。PDF にはノートがないので、元が pptx や Google Slides なら元のファイルかコネクタから取る。取れなければ伝えてから進める。
- ドキュメント・台本: 見出しと段落の構成を書き出す。
- 図は Marp の HTML や SVG で描き直し、描き直せない写真やグラフは元から切り出して貼る。pymupdf で画像を取り出すと透過部分が黒くなることがある（ソフトマスクが別の xref にある）。マスクを合成するか、ページを描画して切り抜く。

## 3. 構成を決める

書く前に、元と新しいページの対応表を作る（元 p3 → 新 p5〜p6、元「2.1」の 3 段落 → ノート）。

- 元の並びがメッセージのあるスライドで終わっていれば、その並びを保つ。元が「ありがとうございました」で終わっていれば、そのページは作らず、直前のメッセージで終える（新しい締めの言葉は足さない）。
- 枚数は時間 ÷ 20〜30 秒。動画にするなら 15〜20 秒/枚でよく、slide-review の秒/枚の指摘は参考にとどめる。
- 1 枚 1 メッセージ。元がドキュメントなら段落ではなく主張ごとに切り、スライドには見出しと結論の一言か図だけを置いて、説明はノートへ。元が台本なら、台本の文はノートに、要点だけをスライドに。
- 元に章立てがなくても、元の見出しの語で中扉を作ってよい。ノートの文を一言スライドにしてもよい（文言は元の範囲で）。
- principal 4.4 のパターン（中扉、段階表示、一言スライド、問いかけ）を流れに合う所で使い、単純な箇条書きは `.cards` にできないか考える。

## 4. 書く

テーマは同梱の `assets/penta.css`（`theme: penta`、書き出しで `--theme-set` に渡す）。

| クラス | 使い方 |
|:--|:--|
| `<!-- _class: center title -->` | 表紙。`<p class="sub">` で副題 |
| `<!-- _class: center chapter -->` | 中扉。`<p class="num">その 1</p>` と `# 章題` |
| `<!-- _class: center big -->` | 一言スライド |
| `.em` / `.ng` | 主色の強調 / アクセント（誤り・注意） |
| `.note` | 出典・注釈 |
| `.box` | ページの結論を入れる箱 |
| `.cards` > `.card` > `.icon` + `.cap` | イラストとキャプションを横に並べる |
| `.two` > `div` | 2 つを並べて比べる（本文は 36px。1 行に収まる短さにする） |
| `.hide` | 段階表示で、次のページで出すものを場所を取ったまま隠す |

- 色を足すなら既存の色の明度違いにする。
- M PLUS 2 にない文字（①〜⑤ などの丸数字、※、₁₂ などの下付き数字、→、℃、○）は環境依存のフォントで描かれ、slide-review に指摘される。数字や w1 のような書き方、テーマの部品に置き換える（伏せ字の ○○ は 〇〇 にする）。コード用の書体を足したときは、その書体にない文字も同じように見る。
- 絵文字は Markdown として書く。`<div class="icon">` のような HTML の中では、絵文字の前後に空行を入れる。HTML のまま書くと Marp が Twemoji の画像にせず、OS の絵文字の書体で描かれる。
- ノート（`<!-- -->`）は 2 つを書き分ける。元の台本や発表者ノートの文は、そのまま読み上げられる形で先に置く（元のノートの見出し行「発表者ノート（目安 60 秒）」などは写さない）。スライドに載せなかった文言は、そのあとに `元 p3: …` の行で置く。台本は発表や VO の下敷きになり、`元 pN:` の行は尺が足りないときに戻す材料になる。
- 元が伏せている値（「○○年」）は伏せたまま書き、確かめたい点として報告する。

## 5. 推敲する

見出しと本文（カードや SVG の中の文言を含む）をテキストに書き出し、yomiyasu スキル（プラグインなら `yomiyasu:yomiyasu`、スキルだけなら `yomiyasu`。種類は slides）で推敲する。作業ディレクトリが Claude Code の作業フォルダの外にあると、yomiyasu の検査はファイルを読まないので、標準入力で渡す。最終稿を確かめてから、1 か所ずつ `slides.md` に写す（置換でまとめて写さない）。引用したプロンプトや指示文は直さず、英語の前後の空白の決まりも当てない。図の代わりに置いた絵文字は残す。ノートは元の文の引用なので推敲しない。6 の評価で直した文は、その文だけ推敲し直す。入っていなければ飛ばし、報告でそう書く。

## 6. 書き出して確かめる

出力先のフォルダで実行する。

```bash
npx -y @marp-team/marp-cli@latest slides.md --no-stdin --html --allow-local-files --theme-set <assets/penta.css> --pdf --pdf-notes -o slides.pdf
```

- `--no-stdin` がないと、エージェントのシェルでは標準入力を待って止まる。M PLUS 2 がなければ代替フォントになるので伝える。
- 対応表で、元の情報がすべてページかノートにあることを確かめる。
- ページ画像で、語の途中の折り返し（「修/正する」）、要素の重なり、図や SVG の端の切れ、段階表示の前後のページで共通部分の位置がそろっているかを見る。
- slide-review の手順で評価し、NG と要改善を直す。評価の間（内容レビューのサブエージェントが読んでいる間を含む）は稿を直さず、指摘がそろってからまとめて直す。計測には `slides.pdf` を渡す（`slides.md` だとテーマなしで描き直される）。PDF からノートは読めないので、内容のレビューには `slides.md` のノートも渡す。

## 7. 報告する

出力ファイルと枚数・秒/枚、対応表、確かめたい点（持ち帰ってほしいことの読み取り、伏せた値、図の読み取り）、評価で残した指摘、実行しなかった推敲や評価。動画にするなら intro-video に進む。
