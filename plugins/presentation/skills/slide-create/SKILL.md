# 資料からスライドを作る

既存の資料から、ぺんたのスタイルの Marp スライドを作る。元がスライドなら作り直し、ドキュメントや台本ならスライドに起こすことになるが、手順は同じ。スタイルの定義は slide-review の `references/principal.md` にあり、この SKILL.md は手順だけを定める。最初に `../slide-review/references/principal.md` を読む。とくに「4.5 既存の資料からこのスタイルのスライドを作るとき」が、何を削り、何を足さないかの決まりになる。

## 1. 入力をそろえる

会話やファイルから読み取れないものは、作り始める前に AskUserQuestion でまとめて訊く。

| 情報 | 必須 | 用途 |
|:--|:--|:--|
| 元の資料 | 必須 | スライド（PDF / pptx / Google Slides / Marp）、ドキュメント（Markdown / PDF / Google Docs / Web ページ）、台本・発表のメモ |
| 使い道と時間 | 必須 | 発表なら発表時間（枚数を決める）。動画にするなら動画の尺（intro-video に渡す） |
| 聴衆 | 必須 | 前提知識に合わせて、スライドに残すものとノートに移すものを決める |
| 持ち帰ってほしいこと | 任意 | 元から一文で言えれば不要。言えなければ訊く（principal の三原則の 1 つ目） |
| 出力先 | 任意 | 指定がなければ元のファイルと同じフォルダに `slides.md` |
| 表紙の名前・SNS アカウント | 任意 | 元にあれば残す。元になければ、ユーザーに言われたときだけ入れる（principal 4.5） |

## 2. 元を読む

- スライド: slide-review の計測スクリプトで、全文・発表者ノート・ページ画像を取る（`python ../slide-review/scripts/analyze.py <元のファイル> <作業ディレクトリ>`。形式ごとの用意は slide-review の SKILL.md の「2. PDF を用意する」）。`analysis.json` に全文とノート、`full/` にページ画像が出る。ページ画像を見て、図・写真・グラフを把握する。
- ドキュメント・台本: 全文を読み、見出しと段落の構成を書き出す。PDF なら pymupdf で文字を、Google Docs ならコネクタか書き出した PDF で読む。図があれば位置と中身を控える。
- 図は、Marp の HTML や SVG で描き直せるものは描き直し、描き直せない写真やグラフは元から切り出して画像として貼る。

## 3. 構成を決める

書く前に、元と新しいページの対応表を作る。元がスライドならページ単位（元 p3 → 新 p5〜p6、元 p4 の表 → ノート）、ドキュメントや台本なら節や段落の単位（元「2.1 背景」の 1〜2 段落 → 新 p4、3 段落 → ノート）。

- 持ち帰ってほしいことを一文で決め、最後のスライドに置く。
- 枚数は、発表時間 ÷ 20〜30 秒（principal 5.3）。動画にするなら、尺 ÷ 20〜30 秒を目安に、ナレーションが付くぶん少し多くてよい。
- 1 枚 1 メッセージにし、見出しを並べると話の流れになるようにする。
  - 元がスライド: 情報の多いページは分け、少ないページはまとめる。
  - 元がドキュメント: 見出しと段落の区切りは、そのままページの区切りにならない。主張ごとに切り、1 枚に置くのは見出しと結論の一言か図にする。説明の文章はほとんどノートに移る。
  - 元が台本: 台本の文はほぼそのままノートになる。スライドには、その区間で話す要点だけを置く。
- principal 4.4 のパターン（中扉、段階表示、一言スライド、聴衆への問いかけ）を、元の話の流れに合う所で使う。問いかけで始まる資料なら、問いを一言スライドにするなど。
- 単純な箇条書きは、テーマの `.cards`（イラストを横に並べてキャプションを付ける形）にできないか考える。順序が大事なら箇条書きのままでよい。

## 4. 書く

- テーマは同梱の `assets/penta.css`（`theme: penta`）を使う。Marp に `--theme-set <このskillのフォルダ>/assets/penta.css` を渡す。テーマのクラス:

  | クラス | 使い方 |
  |:--|:--|
  | `<!-- _class: center title -->` | 表紙。`<p class="sub">` で副題 |
  | `<!-- _class: center chapter -->` | 中扉。`<p class="num">その 1</p>` と `# 章題` |
  | `<!-- _class: center big -->` | 一言スライド |
  | `.em` / `.ng` | 主色（強調） / アクセント（誤り・注意）の文字 |
  | `.note` | 出典・注釈（18pt 相当の 26px） |
  | `.box` | ページの結論を入れる灰色の箱 |
  | `.cards` > `.card` > `.icon` + `.cap` | イラストとキャプションを横に並べる |
  | `.two` > `div` | 2 つを並べて比べる |
  | `.hide` | 段階表示で、次のページで出すものを場所を取ったまま隠す |

  色を足したくなったら、principal 4.3 のとおり既存の色の明度違いにする。新しい色相は足さない。
- スライドに載せなかった文言は、そのページの発表者ノート（`<!-- -->`）に「元 p3: …」「元 2.1: …」の形で移す。捨てない。発表の話の下敷きになり、動画の台本や尺の調整でノートから戻すこともあるため。
- 元にない情報は足さない。具体例、年号、数字、名前を補いたくなっても、元が伏せているもの（「○○年」）は伏せたまま書き、ユーザーに確かめたい点として報告する。
- 本文は 24pt 相当（Marp の 1280px 幅で 32px）以上、注釈は 18pt 相当（24px）以上（principal 5.1）。

## 5. 推敲する

書いたスライドの見出し・本文・ノートを yomiyasu スキル（`yomiyasu:yomiyasu`。presentation プラグインの依存として入る）で推敲する。種類は slides にする。見出しに読点を入れない、などの決まりもここで当たる。推敲の最終稿は別のファイルに出るので、内容を確かめてから `slides.md` に写す。yomiyasu が入っていなければ飛ばし、報告でそう書く。

## 6. 書き出して確かめる

```bash
npx -y @marp-team/marp-cli@latest slides.md --no-stdin --html --allow-local-files --theme-set <assets/penta.css> --pdf --pdf-notes -o slides.pdf
```

- `--no-stdin` がないと、エージェントのシェルでは標準入力を待って止まる。
- M PLUS 2 が入っていなければ代替フォントで描かれる。折り返しが変わるので、入っているか確かめ、なければユーザーに伝える。
- **元と照らす**: 対応表を見ながら、元の情報がすべて、新しいページかノートのどちらかにあることを確かめる。
- **評価する**: slide-review の手順（計測と、スタイルの評価）で `slides.pdf` を評価し、NG と要改善を直す。直したら書き出し直して、もう一度計測する。

## 7. 報告する

- 出力したファイル（`slides.md`、`slides.pdf`）と枚数、秒/枚
- 元と新しいページの対応表（ノートに移したものも含めて）
- 確かめたい点（持ち帰ってほしいことの読み取り、伏せたままにした値、図の読み取り、足さなかった名前など）
- slide-review の評価で残った指摘と、直さなかった理由
- 推敲と評価のうち、実行しなかったもの

動画にする場合は、このあと intro-video の手順に進む。作ったスライドとノートが、台本の下書きになる。
