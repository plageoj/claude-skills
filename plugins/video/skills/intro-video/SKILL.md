# 紹介動画の制作

アプリのデモかスライドを素材に、ナレーション（VO）と字幕の付いた数分の紹介動画を作る。コードは同梱しない。収録スクリプトや Remotion プロジェクトは、この設計に沿ってその場で書く。

1. 入力をそろえる
2. 台本を書く。**ユーザーが直して確定させるまで先に進まない**（「確認を挟まず最後まで」と頼まれたときだけ進め、報告で台本と工程 3 の直し方の表を示す）
3. 字幕を作り、時刻を決める
4. 映像素材を作る
5. VO を用意する
6. Remotion で編集して書き出す
7. 公開前に確認して報告する
8. 直されたら、影響のある工程だけやり直して書き出し直す

| 参照ファイル | 読むとき |
|:--|:--|
| `references/source-app.md` | アプリのデモを Playwright で収録するとき |
| `references/source-slides.md` | スライドを素材にするとき |
| `references/audio.md` | VO を作る・受け取るとき、音量をそろえるとき |
| `references/remotion.md` | 編集・書き出しをするとき |

## 1. 入力をそろえる

読み取れないものは、台本の前に AskUserQuestion でまとめて訊く。言語や尺が後から変わると全部作り直しになる。

- 目的と提出先（尺の上限、形式、AI 生成物の可否）
- 素材: アプリ（起動方法と URL）かスライド。スライドなら、そのまま使うか作り直すか（`references/source-slides.md`）
- 音声と字幕の言語（毎回訊く。例: 英語音声＋日本語字幕、字幕なし）と視聴者
- 書き出す版: 字幕あり（焼き込み）、字幕なし、両方のどれか。決めた版だけを書き出す
- VO: srt-dubbing で合成するか、録音を渡すか
- 触れてはいけないもの（未リリースの機能、非公開の情報）
- 任意: ユーザーが用意するカット、BGM（ユーザーが権利を持つ曲）、実測値（推測で書かない）

## 2. 台本を書く

作業ディレクトリ（例: `video/`）に `scripts.md` を書く。対象アプリのリポジトリに置くなら、コミットするかを確かめる。SRT はまだ作らない。

- 尺の見込み、シーン表（時刻の目安 / 内容 / 画とその出どころ）、ナレーション原稿（キューに区切らない）、間を置く所（指定した所にだけ置く）、収録の指示
- 数分の動画なら、つかみ（10〜15 秒）→ 課題 → タイトル → デモ → 特徴 → 締め、が基本
- ショートカット・メニュー名・画面の文言は、ソースコードか実際の画面で確かめる。ドキュメントは実装と食い違っていることが多い
- **素材にない人物の情報を足さない**。名乗り、自己紹介、クレジット、締めの名前は、素材に自己紹介のページや作者の表記が明示されているときだけ入れる。表紙に名前があるだけなら映すにとどめ、読むかは訊く。Remotion で描く締めのカードにも足さない
- 渡す前に、原稿を yomiyasu スキル（プラグインなら `yomiyasu:yomiyasu`、スキルだけなら `yomiyasu`。種類は決めない。script は台詞の決まりなのでナレーションに合わない）で推敲する。作業ディレクトリが Claude Code の作業フォルダの外にあると、yomiyasu の検査はファイルを読まないので、標準入力で渡す。SRT を作ってから推敲すると、読み上げに写して合成し直すことになる。事実と数字が変わっていないかは読み比べる。読点は TTS の間になるので、推敲で外れた読点のうち間として要るものは、読み上げ用の原稿（工程 3）に残してよい。入っていなければ飛ばし、報告でそう書く
- 渡すときに頼む: スライドにない話の追加（発表者ノートや発表の録音があれば下敷きにする）、解釈して言い換えた箇所の確認（引用・詩歌・キャッチコピーは言い換えない）、読み方の分からない語

## 3. 字幕を作り、時刻を決める

台本が確定したら、`scripts.md` のナレーションを 1 キュー 1 行に書き換え（下の「直せるようにしておく」）、それを読んで SRT を書き出すスクリプト（例: `build_srt.py`）を作る。文言はスクリプトに書き写さず、スクリプトには読み（字幕と同じなら省略）と、キューとシーンの対応だけを持たせる。

- `scripts.vo.srt`: 読み上げ用（srt-dubbing に渡す）
- `scripts.<字幕の言語>.srt`: 焼き込む字幕。音声と同じ言語でも読み上げ用とは別にする（字幕に「マイエスキューエル」は出せない）
- すべての SRT でキュー番号と時刻をそろえる。1 キューは 1〜2 行、日本語で 1 行 16〜20 字（英数字は 0.5 字と数える）、文の切れ目で分ける

### 読み上げ用の書き方

- 英字・略語・記号は読める形に開く（MySQL → マイエスキューエル、`SQLite` → `S Q Lite`）。何度も出る語は置き換えの表にしてスクリプトの頭に置き、読みのないキューに当てる
- 数字＋単位・助数詞（「4年目」「10月」「0.2%」）は、かなに開かず数字のまま渡す。開くとアクセントが崩れる
- 同音の語は、かなに開かず漢字かカタカナで渡す（「はし」は「橋」「箸」「ハシ」）。かなだけだと別の語で読まれる（「わし」になった）

### 時刻は音声の長さから決める

字幕を読む速さから決めない。TTS は速いので、無音だらけになる。

- 合成: 仮の時刻で一度合成して長さを測り、組み直して合成し直す（手順は `references/audio.md`）。キューの長さ = 音声の長さ（末尾の無音を除く）＋0.1 秒。キューのあとの間:

  | キューのあと | 空ける秒数 | 耳で聞いた長さ |
  |:--|--:|--:|
  | 文の途中（読点で終わる、句読点なし） | 0.1 | 約 0.4 秒 |
  | 文の終わり | 0.3 | 約 0.6 秒 |
  | スライド・シーンの切り替え | 0.9 | 約 1.2 秒 |
  | セクションの切り替え | 1.2 | 約 1.5 秒 |
  | 台本の `⏸` 行 | 上の値＋その秒数 | |

  耳で長く聞こえるのは、音声の頭に約 0.2 秒の無音があるため。文の途中を短くするのは、TTS がキューの中の読点で置く間（約 0.4 秒）にそろえるため。
- 録音: 録音を先にもらい、発話の区間（`silencedetect`）から決める
- 字幕が 1 秒 10 字（英数字は 0.5 字に数える）を超えるキューは、短くするか分けるよう提案する（音声付きなら 9.5 字/秒でも気にならなかった）
- 尺が見込みと 15% 以上違えば、TTS の速さと台本の量のどちらで合わせるかを訊く
- 番号の連続、時刻の単調増加、重なりのなさをスクリプトで確かめる。シーン表の時刻を実際の値に直す

### 直せるようにしておく

`scripts.md` のナレーションは 1 キュー 1 行にし、文言と間をそこで直せるようにする。字幕を 2 行に分ける所は、行の中に `／` を入れる。音声と字幕の言語が違うときは、1 行に読み上げと字幕を ` ｜ ` で区切って書く。

```markdown
### 背景（p3〜p6）

- `33` 結果がこちらです。
- ⏸ 3 秒
- `34` 処理時間は、半分になりました。
```

- 自動の間（上の表）より長く置く所にだけ `⏸` 行を書く。`###` はセクションの切り替えになる。スクリプトはこの行と見出しを読んで時刻を組み、秒数を自分では持たない
- 文言と間の正本は `scripts.md`、読みはスクリプト、時刻は書き出した SRT。読みを持つキューの字幕が変わったら、スクリプトが警告を出す（読みが古いまま残るため）
- スライドとコードで描くシーンは、区間と演出をキュー番号に結び付ける（秒数で書くと組み直すたびにずれる）。収録のテイクは台本の秒数で決める
- SRT を渡すときに、次の表を添える（工程 8 でもこれに従う）

| 直したいもの | 編集するファイル | やり直す作業 |
|:--|:--|:--|
| 字幕の文言・改行 | `scripts.md`（SRT を直接直すと、次にスクリプトを流したとき消える） | スクリプトを流して書き出し直す。音声と字幕が同じ言語なら、読みにも写して VO を作り直す（推敲で読点を削っただけでも写す）。字幕だけ直したいと言われたら写さない。VO の長さが変わったら、そのキューより後ろのアプリのテイクを撮り直す |
| 字幕の表示時刻 | すべての SRT | 書き出し直し。合成なら VO も作り直す |
| ナレーションの文言や読み | スクリプトの読み | 合成なら変わったキューを作り直して時刻を組み直す。録音なら録り直しを頼む。長さが変わったら、そのキューより後ろのアプリのテイクを撮り直す |
| 間 | `scripts.md` の `⏸` 行 | 合成なら組み直して合成し直す（キャッシュで並べ直すだけ）。録音なら録音に無音を挟んで時刻を取り直す。アプリのテイクは台本の秒数で撮るので、その `⏸` 行より後ろのテイクを撮り直す |
| シーンの画 | `scripts.md` のシーン表 | 該当するシーンのコードか収録だけ直す |
| 話の中身を大きく | `scripts.md` | 工程 3 からやり直す |
| キューの追加・削除 | `scripts.md`（読みを持つキューは、スクリプトの番号も直す） | ずれた番号に結び付けたページ・強調・シーンの番号もずらす。すべての SRT の対応を確かめ、合成の VO は全体を作り直す。録音なら録り足すか切り取りを頼んで時刻を取り直す |

## 4〜6. 素材、VO、編集

- アプリは `references/source-app.md`、スライドは `references/source-slides.md`。スライドでは、ライブで話し手が担っていたもの（めくるタイミング、指し示し）を動画で受け持つ
- VO は `references/audio.md`。動画の 0:00 から並んだ 1 本（`public/vo.mp3`）にそろえる
- 編集は `references/remotion.md`。工程 1 で決めた版だけを書き出し、両方なら 1 本ずつ順に書き出す（同時に書き出すと CPU を取り合って遅くなる）。字幕なしの動画でも、字幕用の SRT は時刻の対応のために作る

## 7. 公開前に確認して報告する

- 尺（ffprobe）、ラウドネスとピーク（`ebur128`。-14〜-16 LUFS、ピーク -1 dBFS 以下が目安）
- 画像を見て確かめる作業（静止画、コンタクトシート）は、Agent ツールが使えればサブエージェントに任せる。画像のパスと、見ること（キュー番号と字幕の文言、枠を置いた要素）を渡し、問題のある所だけを文で返してもらう。画像を見るたびに本体の文脈が膨らみ、そのあとの全部の手順が重くなるため
- 字幕と強調は、書き出す前に静止画で確かめておく（`references/remotion.md`。フォントの代替やはみ出しは見ないと分からない）。書き出したものは、数か所のフレームで映っていることだけを見る。MP4 から切り出すなら `-ss` を `-i` の前に置く（後ろに置くと頭から読み進めて遅い）
- 映り込み: AI 生成の透かし、個人情報（通知、タブ、ファイル名、メールアドレス）、未リリースの機能、台本と違うデータ。見つけても勝手に消さず訊く
- 権利: BGM、フォント、スライドの絵文字（Marp は Twemoji の画像にする。CC-BY 4.0 でクレジットが要る）、AI 生成物と Edge TTS の利用条件、提出先の規定、Remotion のライセンス（`references/remotion.md`）

報告では、確かめたことと確かめていないこと（見ていないフレーム、推定で置いた値）、判断を待つ項目を分ける。VO の読みは聞いてもらうしかないので、聞いてほしいキューを並べる。

## 8. 直されたら書き出し直す

1. 変わったものを、`out/` に控えた SRT や git と中身で比べて特定する（更新日時では決めない）。言われたのに変わっていないファイルは報告で触れる
2. SRT を工程 3 の確認にかける。崩れていたら書き出さず、どのキューかを示す。ユーザーの文言はこちらで書き換えない
3. 工程 3 の表に従ってやり直し、書き出し、工程 7 の確認をする。直した字幕はフレームで映っていることを見てから報告する
