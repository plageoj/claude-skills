# アプリのデモを収録する

ブラウザで動くアプリを Playwright で操作し、台本の時刻どおりのテイクを撮る。デスクトップアプリも、同じ UI のブラウザ版があればそれを撮る。実機でしか見せられないもの（起動の速さ、ウィンドウの開閉）は、ユーザーに手持ち素材として撮ってもらう。

## 収録スクリプト

1 本の Node スクリプト（例: `video/record-demo.mjs`）にまとめる。Playwright は対象リポジトリに入っていれば `createRequire` で読む。

- **タイムライン**: `[時刻, 操作]` の配列に、VO の一節をコメントで添える。台本の時刻（動画全体の秒数）からテイクの開始時刻を引いて、テイクの中の時刻にする。`performance.now()` でその時刻まで待って実行し、過ぎていたら遅れを警告する。最後の操作のあとはテイク終了時刻まで待つ。
- **準備は画面外で**: ログイン、表示の設定、デモ用データ（実在の人名・メールアドレスは使わない）、未リリース機能のボタンを隠す（`display: none` を注入）。
- **キャプチャ**: `recordVideo` は画質が低く fps も揺れるので使わない。CDP の `Page.startScreencast` で PNG を時刻つきで受け取り、一定間隔の時刻ごとに「その時刻以前で最後のフレーム」を並べて 60 fps の連番にする（ハードリンクでよい）。ffmpeg で H.264（`-crf 12 -preset slow -pix_fmt yuv420p`）にする。
- **逃げ道とデバッグ**: `--live` でブラウザを表示して実行し OBS などで撮れるようにする。`DEBUG=1` で各操作のあとのフォーカスや開いている画面をログに出す。

## 操作をページに描いて見せる

Playwright の入力は OS を通らないので、キー表示ツールにもマウスカーソルにも映らない。`page.addInitScript` で注入した要素で描く。テイク開始時にフラグを立ててから表示し、準備中の操作は映さない。

- キー操作: `keydown` を拾って画面の隅に `Ctrl+Shift+P`、`Shift+L` のように出す。
- マウス操作: 偽のカーソルを描いてクリックの位置に波紋を出す。`page.mouse.move(x, y, { steps })` で動かし、クリックの前に 0.2〜0.3 秒止める。

## 注意

- 先に短い探りのスクリプトで、操作ごとの画面の変化（入力欄まで開くか、待ちが要るか、一覧の端でどこに行くか）を確かめてからタイムラインを組む。
- 文字の入力は 1 文字 35〜80 ms。
- 通信を伴う操作は、デモ用データをローカルかモックで返して時刻のぶれをなくす。
- キー操作のアプリで、ダイアログをマウスで閉じるとフォーカスが外れてキーが効かなくなることがある。開閉の手段をテイク中とそろえる。
- Windows では、シェルのカレントディレクトリが出力先の中にあるとディレクトリごと消せない（EBUSY）。中身だけを消す。
- 撮ったら数か所のフレームを切り出し、操作の結果、キー表示やカーソル、隠したはずのボタンを確かめる。
