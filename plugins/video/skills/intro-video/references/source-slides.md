# スライドを素材にする

スライドをページごとの画像にし、台本の時刻に合わせて Remotion で切り替える。スライドの見た目をそのまま使えるので、作り直すより早く、発表資料と動画の内容がずれない。

## ページ画像にする

1920×1080 の PNG にする。16:9 でないスライドは、余白を背景色で埋めて中央に置く（引き伸ばさない）。

| 形式 | 方法 |
|:--|:--|
| PDF | `pdftoppm -png -scale-to-x 1920 -scale-to-y -1 slides.pdf out/slide`、または pymupdf で 1920px 幅に描画 |
| Marp（`.md`） | `npx @marp-team/marp-cli slides.md --images png --image-scale 1.5`（解像度は `--image-scale` で調整）。日本語フォントと Chrome が要る |
| pptx | LibreOffice（`soffice --headless --convert-to pdf`）で PDF にしてから PDF と同じ手順。フォントの置き換えで折り返しが変わるので、ユーザーに PowerPoint から書き出した PDF をもらえるならその方がよい |
| Google Slides | 共有リンクが公開なら `https://docs.google.com/presentation/d/<ID>/export/pdf` を取得して PDF と同じ手順。非公開なら「ファイル > ダウンロード > PDF」で書き出してもらう |

画像は Remotion の `public/slides/01.png …` に置く。

書き出したら一覧（コンタクトシート）を作って見る。フォントの代替、絵文字の欠け、はみ出しは画像を見ないと分からない。

### 位置を PDF から取る

強調する行や、寄る先の図の位置は、画像を見て測らずに PDF から取る。pymupdf の `page.get_text("dict")` で、行ごとの文字と外接矩形、画像の矩形が得られる。1920 / ページの幅を掛ければ、書き出した PNG の座標になる。

```bash
uv run --with pymupdf python -c "
import pymupdf
d = pymupdf.open('slides.pdf')
for n, p in enumerate(d, 1):
    z = 1920 / p.rect.width
    for b in p.get_text('dict')['blocks']:
        r = [round(v * z) for v in b['bbox']]
        if b['type'] == 1: print(n, 'IMG', r)
        else:
            for l in b['lines']:
                print(n, [round(v * z) for v in l['bbox']], ''.join(s['text'] for s in l['spans']))
"
```

Windows ではコンソールの文字コードで落ちるので、`PYTHONIOENCODING=utf-8` を付ける。

図形（段階表示で足される箱など）の矩形は `page.get_drawings()` の `rect` で取れる。グラフや図が画像として貼られているときは、中の線の位置は PDF にない。指し示しに折れ線の座標が要るなら、PNG の画素から線の色を列ごとに拾い、上下の端の中点をつないで点列にする（4px おきで十分なめらか）。拾った点列は JSON に書き出し、静止画で線に重なっているか確かめる。

### 動画に出さないもの

会場向けの表示（撮影禁止のマーク、QR コードの「その場で読んでね」など）は、動画では意味がなかったり誤解を招いたりする。台本を書く段階でユーザーに残すかを訊き、隠すなら Remotion でスライドの背景色の矩形を上に重ねる（背景色は PNG の画素から取る）。画像そのものは書き換えない。

## 台本との対応

- 台本のシーン表に、区間ごとに映すページ番号を書く。
- ページは動かさず、淡々とめくる。スライドの見た目をそのまま見せるのが、スライドから動画を作る意図に沿う。常にゆっくり拡大する（Ken Burns）と、端にあるロゴやブランドのあしらいが切れ、スライドの体裁が崩れる。1 ページを長く映すときは、ページの一部を順に強調する演出で、止まって見えないようにする。
- 拡大は、グラフや写真を見せるといった意図があるときだけ使い、台本の「画」の欄に書く。
- スライドのアニメーション（段階表示）は画像にすると消える。必要なら、段階ごとに別のページとして書き出すか、Remotion で該当部分を重ねて表示する。同じスライドを複数枚繰り返して差分を足す段階表示（ぺんたのスライドによくある）は、下の「段階表示は声に合わせて出す」に従う。
- 台本の多くがスライドに書かれていない発表（話しながら見せるスライド）では、スライドにない話の間、画が止まる。文字を足すと「読ませるスライド」になってしまうので、下の「スライドにない話は指し示す」で補う。
- 発表者ノートがあれば、VO 原稿の下書きに使える。ただし話し言葉の発表と、字幕つきの動画とでは長さが違うので、キューの長さに合わせて詰める。
- スライドに小さい文字（出典、注釈）があるなら、動画では読めないことが多い。読ませたいものは VO か字幕で補う。

## Remotion での並べ方

ページごとに `<Img src={staticFile("slides/03.png")} />` を置き、表示する区間を決める。

- **区間はキュー番号で決める**。ページごとに最初のキュー番号を持たせ、そのキューの開始の 0.5 秒前から次のページの開始までを区間にする。時刻を組み直しても、ページが声についてくる。ページ番号と最初のキュー番号の対応表を `scripts.md` に残す。
- **切り替え**は 0.3〜0.5 秒のクロスフェードを基本にし、台本のセクションの頭でだけ長め（0.8 秒程度）にする。後のページを上に重ね、前のページは不透明のまま残して、後のページだけをフェードインさせる。
- **強調**は、`[最初のキュー, 最後のキュー, ページ, 矩形]` の表にして、キューの開始から終了まで、行の上に半透明のマーカー（`mixBlendMode: "multiply"`）を出す。矩形は上の「位置を PDF から取る」で取る。同じ行を続くキューで強調するなら 1 項目にまとめ、点滅させない。
- **強調は上から下へ一方向に進める**。聞き手はスライドを上から読み、話し手が下へ進むのを目で追っている。強調が上に戻ると、話は進んでいるのに「前に戻った」「読み飛ばした」ように見える。表を書いたら、同じページで矩形が上に戻る箇所を探し、次のように直す。
  - 話す順が箇条書きの順と前後する: 前後する行をまとめて 1 つの枠にし（外接矩形を合わせる）、それらのキューの間ずっと出す。原稿を箇条書きの順に入れ替える手もあるが、話の運びが変わるので、ユーザーに訊いてから。
  - まとめの一言で見出しに戻る: 見出しは強調しない。最初から見えているので、声で届けば十分。
  - 言い換えで行をもう一度なぞる、といった意図した振り返り: 上に戻ってよい。表にそうコメントを書いておく。
- **段階表示は声に合わせて出す**。前のページと同じスライドに何かを足しただけのページ（問いの箱、オチの一言など）は、0.5 秒前に先回りしてめくると、声より先に答えが見えてしまう。ライブなら「言ってからクリック」の場面なので、次のようにする。
  - ページの区間は、その足された部分を言うキュー（ページの最初の話題ではなくてよい）から始める。開始はキューの頭 + 0.1 秒（合成音声はキューの頭に約 0.18 秒の無音がある）、クロスフェードは 0.25 秒と短く。共通部分は同じ画素なので、足された部分だけが現れたように見える。
  - それまでのキューは前のページのまま映す。足されたページで色が変わる行（青字にした行など）があれば、その行を前のページで強調しておき、めくる瞬間まで出し続ける。目線が強調から色の変化へそのまま続く。
  - `SLIDES` の項目に `reveal: true` のような印を持たせ、区間とフェードの計算を分ける。
- **スライドにない話は指し示す**。ライブなら手やポインタで示していた動きを足す。画面の文字は増やさない。
  - 問いや主張を受けて話が続くとき（「それはエンジニアだけではわかりません」）: 関係する行をまとめて薄く強調する。
  - 「だから」「つまり」のつなぎ: 矢印や記号がスライドにあれば、そのキューで矢印と次の行を強調する。
  - 締めの言葉（「それが、これからを生き抜く力になります」）: 結論の行をまとめて、ページの終わりまで強調する。
  - グラフの推移（「少しずつ伸びてきました」）: 寄ったあと、そのキューに合わせて折れ線をマーカーでなぞる（SVG の `polyline` の `strokeDashoffset` を `interpolate` で動かす）。点列は上の「位置を PDF から取る」で取る。
  - どれも「強調は上から下へ」を守る。下まで進んだあとに上の行へ戻る指し示しは、つなぎのキュー（「だから」）に前倒しする。
- **寄り**: 図や写真を見せる場面では、そのキューが終わってから 1.5 秒前後かけて寄る。`transformOrigin` を図の中心に置いて `scale` を上げる。見出しが端で半分切れていないか、静止画で確かめる。
- 強調・なぞり・寄り・隠す矩形は、すべてスライドと同じ拡大の中に置く。寄っている間も位置がずれないようにするため。

### 字幕とスライドを重ねない

スライドは画面いっぱいに文字や図があることが多く、下に字幕を重ねると隠れる。スライドを 86% 程度に縮めて上に寄せ、下に空いた帯（1080 の 14% で約 150px、2 行の字幕が収まる）に字幕を出す。帯は濃い色にし、左右の余白も同じ色で埋める。字幕なし版では帯が要らないので、スライドを縮めずに画面いっぱいに出す（字幕の有無の props で縮める率を切り替える）。スライドの下の方に何もないなら、縮めずに重ねてもよい。
