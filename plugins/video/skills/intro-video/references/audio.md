# VO と音量

VO は、動画の 0:00 から台本の時刻どおりに並んだ 1 本のファイル（`public/vo.mp3`）にそろえる。キューごとに切ったファイルで管理するより、ずれを確かめやすく、録音ファイルと合成のどちらでも同じ扱いにできる。

## srt-dubbing で合成する

[plageoj/srt-dubbing](https://github.com/plageoj/srt-dubbing) は、SRT の各キューを Microsoft Edge TTS で読み上げ、キューの開始時刻に並べた音声を作る。API キーは要らない。必要なのは Python 3.10 以上、ffmpeg、uv（なければ `pip install .`）。

```bash
git clone https://github.com/plageoj/srt-dubbing.git
cd srt-dubbing
uv run viet_dubbing.py --srt <作業ディレクトリ>/scripts.vo.srt --voice en-US-AndrewNeural --audio-only
```

- 渡すのは読み上げ用の SRT（`scripts.vo.srt`）。視聴者向けの字幕の SRT ではない。
- 読み違いは合成した音声を聞かないと分からない。英字・略語・人名・数字を含むキューを先に数個合成して聞き、読みを直してから全体を合成する。
- 数字＋単位・助数詞（「2023年4月」「4年目」「10月」「0.2%」）は数字のまま渡す。「よねんめ」「じゅうがつ」のようにかなに開くと、区切りやアクセントが崩れて不自然になりやすい。開くのは、数字だけで読み方が決まらないもの（バージョンの「2系」を「にけい」と読ませたいときなど）に限り、聞いて確かめる。
- `--voice` には edge-tts の音声 ID を渡す。一覧は `uv run edge-tts --list-voices`。`female` / `male` はベトナム語の音声の別名なので使わない。候補を 2〜3 個合成して、ユーザーに選んでもらうとよい。
- `--audio-only` では `--out` が効かず、SRT 名と時刻から付いた名前の MP3 ができる。それを `public/vo.mp3` にコピーする。
- 合成した音声はキューごとにキャッシュ（`tts_<SRT 名>/cue_<4 桁の番号>.mp3`）に残り、中断しても続きから作り直せる。
- Edge TTS はキューごとの音声の末尾に約 0.9 秒の無音を付ける。srt-dubbing（f7a39d8 以降）はこれを削ってから長さを測り、並べる。頭の約 0.2 秒の無音は残る。
- キューの表示時間より長い音声（末尾の無音を除く）は速められる（最大 2 倍）。時刻を音声の長さから組めば（下記）速められることはない。

### 時刻を音声の長さから組む

キューの時刻を先に決めてから合成すると、音声がキューに足りずに無音が残るか、はみ出して速められる。時刻は合成した音声の長さから決める。

1. 台本の原稿から、仮の時刻で `scripts.vo.srt` を作る。各キューは十分長く取る（1 秒 4 字程度で割った長さ）。
2. 合成する。キューごとの音声（`tts_scripts.vo/cue_*.mp3`）の長さを、srt-dubbing と同じく末尾の無音を除いて測る。ffprobe のファイルの長さをそのまま使うと、すべての間が約 0.9 秒ずつ延びる。

   ```bash
   ffmpeg -hide_banner -nostats -i cue_0001.mp3 -af silencedetect=n=-50dB:d=0.1 -f null -
   ```

   最後の `silence_start` がファイルの終わりまで続く無音の始まり。その時刻＋0.05 秒を音声の長さにする（キャッシュのファイルは書き換えない）。
3. 音声の長さに合わせて時刻を組み直す。キューの長さ = 音声の長さ＋0.1 秒。キューのあとの間は、文の途中で切れたキュー 0.1 秒、文の終わり 0.3 秒、スライドの切り替え 0.9 秒、セクションの切り替え 1.2 秒に、台本の `⏸` 行の秒数を足す（理由は SKILL.md の工程 3）。字幕用の SRT にも同じ時刻を入れる。
   - 耳で聞いた間は、頭の無音のぶん約 0.2 秒長くなる。間を測って確かめるときは、書き出した音声に `silencedetect=n=-50dB:d=0.2` をかける。
   - TTS が 1 キューの中で置く間は、ja-JP-KeitaNeural で読点約 0.4 秒、句点約 1 秒だった。声を変えたら、数キューで測ってから文の途中の間を決める。
4. 組み直した `scripts.vo.srt` で再実行する。文言は変わっていないのでキャッシュがそのまま使われ、並べ直しだけが行われる。

この手順は、測った長さから SRT を書き出すスクリプト（工程 3 の `build_srt.py` など）に組み込んでおく。原稿を直して一部のキューを作り直したときも、同じスクリプトで後ろの時刻を組み直せる。

### 原稿を直したあとに作り直す

キャッシュはキュー番号だけで引かれ、文言が変わっても使い回される。原稿を直したら、作り直すキューのキャッシュを消してから同じコマンドを再実行する。

- 文言を直したキュー: `cue_<番号>.mp3` と、あれば `cue_<番号>.mp3.fast`（速めて作り直した目印）を消す。消していないキューは合成し直されないので、変わったキューだけが作り直される。
- 時刻だけを直したキュー: キャッシュはそのままでよい。並べ直しと伸縮は毎回やり直される。
- 文言を直したキューは音声の長さが変わるので、作り直したあとに時刻を組み直す（上記の 3〜4）。
- キューの追加・削除で番号がずれた: 番号と文言の対応が崩れるので、`tts_<SRT 名>/` ごと消して全体を作り直す。

変わったキューは、前回の SRT と比べて見つける（git 管理していれば `git diff`、なければ前回の書き出し時に SRT を `out/` に控えておいて比べる）。作り直したら新しい MP3 を `public/vo.mp3` にコピーし、`public/norm/` の音量をそろえたファイルが作り直されることを確かめる。

## 録音ファイルを受け取る

ユーザーが録音した場合は、次を確かめてから使う。

- **位置**: 0:00 から台本の時刻どおりに並んでいるか。ffmpeg の `silencedetect` で発話の区間を出し、各キューの開始時刻と比べる（0.1〜0.2 秒程度のずれは問題ない）。大きくずれていれば、キューの時刻の方を録音に合わせるか、録音を切って並べ直すかをユーザーに訊く。
- **長さ**: 動画の尺に収まるか。
- **キューごとのファイル**: 1 本にまとめられていなければ、`public/vo/<キュー番号>.mp3` として受け取り、キューの開始時刻に置いてもよい。

## 音量をそろえる

VO と BGM は音源ごとに音量がばらばらなので（例: VO -25 LUFS、BGM -9 LUFS）、編集の前に ffmpeg の `loudnorm` で同じ基準にそろえる。

```bash
ffmpeg -y -i vo.mp3 -map 0:a -af loudnorm=I=-16:TP=-1.5:LRA=11 -ar 48000 norm/vo.wav
```

両方を -16 LUFS にそろえておけば、Remotion で指定する音量は「VO に対して何 dB 下げるか」として読める。

- BGM は VO より 15 dB 下（音量 0.178）を出発点にする。声が埋もれるなら 18 dB 下（0.126）まで下げる。
- BGM は VO が始まる少し前から 1.5 秒かけて入れ、最後の数秒でフェードアウトする。
- VO に合わせて BGM を下げる処理（ダッキング）は、ユーザーが望んだときだけ入れる。BGM の聞こえ方が変わるのを嫌う人もいる。
- 書き出したら `ffmpeg -i final.mp4 -af ebur128=peak=true -f null -` で全体のラウドネスとピークを測って報告する。
- BGM はユーザーが権利を持つ曲を使う。音楽の生成や、フリー素材の選定は頼まれたときだけ行う。
